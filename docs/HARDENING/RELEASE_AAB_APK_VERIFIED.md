## Changes on the current PR branch

- Gradle now loads signing configuration from ignored `pos-app/android/key.properties`.
- The main-branch release workflow expects these GitHub Actions secrets: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. The keystore and properties are created only in the runner workspace and are not committed.
- Pull-request validation builds unsigned AAB/split APK packages without exposing release signing secrets.
- A main-branch release, when signing secrets exist, builds an obfuscated AAB and split APKs, verifies signatures using `jarsigner` and `apksigner`, then uploads `app-release.aab`, `app-arm64.apk`, `app-x86_64.apk` and debug symbols.
- If signing secrets are absent, the workflow explicitly skips signed artifacts and writes a warning/step summary; that outcome is not production acceptance.
