## CI and image changes

- Pin PHP 8.4 and Composer build inputs; use a common Dockerfile/runtime family for CI and production.
- CI and production require the committed `composer.json` / `composer.lock` pair. Missing lockfile or manifest/lock disagreement fails the build.
- Require `composer validate --strict --no-check-publish`, a clean ordinary locked `composer install` with scripts enabled, `composer check-platform-reqs`, and `composer audit --locked`.
- Use fresh Composer home/cache locations in install steps and no Actions dependency cache, preventing a warm cache from hiding lockfile or install inconsistencies.
- Add fail-closed static checks for the approved root constraints, locked framework/Filament versions, exact tenancy v3.10.1, platform requirements, lockfile presence, and prohibited advisory/platform-policy suppression.
- Include the root `artisan` entrypoint in PHP syntax checks and correct its malformed Symfony Console import.
- Align Filament resources with Filament 5 schema/navigation/action API changes and remove the nonexistent `TenantWithDomains` interface from the custom tenant model; v3.10.1 provides domain behavior via its `HasDomains` trait.
- Remove a redundant global-namespace `use RuntimeException;` from a migration because Laravel escalates the PHP warning to an exception at migration load.
- Add a separate `production-image` job so image build and boot/route/locked-version smoke checks still execute even when the MariaDB integration suite fails.
- Run the repository-wide Pint check after application acceptance gates, so legacy formatting findings cannot prevent the locked install, migrations, tests or image build from executing. Pint remains a gate and was also run in the temporary source-normalization workflow.
