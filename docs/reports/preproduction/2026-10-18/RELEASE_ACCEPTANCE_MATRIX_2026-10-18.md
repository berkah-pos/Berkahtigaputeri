## Status vocabulary

- **VERIFIED:** directly proved for the stated scope and exact revision/environment.
- **CLAIMED:** stated by a document/person but not independently established here.
- **FAILED:** an executed check failed or the implementation conflicts with an explicit mandatory policy.
- **BLOCKED:** cannot be accepted because a prerequisite, implementation, decision or required evidence is missing.
- **NOT RUN:** the required test/operation was not executed.
- **NOT APPLICABLE:** only for a scope formally excluded and approved; exclusion does not mean the control passed.

A passing check on an open PR, its merge commit, an old SHA or a narrower test scope does not make the gate PASS on `main` or on a different candidate.

## Candidate release rule

A proposed label is **`v1.0.0-rc1` (PROPOSED / NOT TAGGED)** for a first controlled release candidate. It is not permission to tag or publish. The existing Android Gradle metadata is `versionName=1.1.0`, `versionCode=2`, package `id.co.berkahtigaputeri.berkahpos`; the owner must choose the release-version relationship and prove signing compatibility before any artifact is distributed.

**General SaaS Go** only when all P0 gates and all applicable P1 gates are verified at the same exact candidate SHA, there are no open P0s, and business-owner approval is recorded. A limited local-only pilot is a different release scope: it still needs P0 financial correctness, offline-safety, release-artifact/signing, security and UAT gates; it must disable/unclaim cloud login/config/sync/subscription and clearly disclose device-local data. Do not label a local-only build a multi-tenant SaaS release.
